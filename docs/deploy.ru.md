# Как развернуть VPN

Два сервера: **входной** (к нему подключаются клиенты) и **выходной** (с него трафик уходит в интернет). Всё ставится с вашего компьютера скриптами по ssh. Руками на серверах ничего делать не нужно.

Как устроена сеть — в [network.ru.md](network.ru.md).

## 1. Что нужно

### Серверы

| | Входной | Выходной |
| --- | --- | --- |
| ОС | Ubuntu 24.04 LTS, чистая | Ubuntu 24.04 LTS, чистая |
| Ресурсы | от 1 vCPU, 1 ГБ RAM | от 1 vCPU, 1 ГБ RAM |
| Доступ | ssh-пользователь с `sudo` без пароля | то же |
| Открыть в облачном firewall | UDP 443 (клиенты), TCP 22 (ssh) | UDP-порт туннеля (лучше только с IP входного), TCP 22 |

Порт туннеля случайный (20000–60000). Он появится в `secret/tunnel.yaml` (строка `port:`) после шага 3.

Если на сервере включён `ufw`, деплой сам откроет в нём нужные порты (UDP 443 на входном, порт туннеля на выходном). Облачный firewall открывайте сами.

Всё остальное (модуль ядра AmneziaWG, `awg`/`awg-quick`, `nftables`, `unbound`) ставит деплой.

### Ваш компьютер

macOS или Linux, и программы: `bash`, `ssh`, `openssl` 3 (с X25519), `qrencode`, `shellcheck`, `make`. Если входите на сервер по паролю, а не по ключу, — ещё `sshpass`.

На macOS:

```bash
brew install openssl qrencode shellcheck   # sshpass — только для входа по паролю
```

## 2. Проверка проекта

```bash
make test    # все тесты скриптов, серверы не нужны
make lint    # shellcheck
```

## 3. Ключи и доступы

```bash
./scripts/vpnctl.sh init
```

Команда создаёт в папке `secret/` (её нет в git):

- `entry-access.yaml` и `exit-access.yaml` — шаблоны доступа к серверам;
- `tunnel.yaml` — ключи туннеля между серверами, PSK, порт, параметры обфускации;
- `clients/` — сюда будут падать конфиги клиентов.

Уже существующие файлы команда не трогает.

Заполните оба файла доступа:

```yaml
host: 203.0.113.10
port: 22
user: deploy
# password: ...   # только если нет ssh-ключа
```

### Подключение клиентов по доменному имени

Чтобы клиенты подключались не по IP, а по имени (например, `vpn.example.com`):

1. У регистратора домена создайте A-запись `vpn.example.com` → IP входного сервера.
2. Добавьте в `secret/entry-access.yaml`:

   ```yaml
   endpoint: vpn.example.com
   ```

После этого `vpnctl.sh add` пишет в конфиг клиента `Endpoint = vpn.example.com:443`. ssh и деплой по-прежнему идут на `host:`. Если `endpoint:` нет — клиенты получают `host:`.

Так входной сервер можно сменить без перевыдачи ключей: перенесите `awg0.conf` и поменяйте A-запись. Уже выданные конфиги с IP сами не меняются: перевыдайте их (`remove` + `add`).

Выходной сервер тоже можно указать по имени (`host:` в `exit-access.yaml`): тогда входной сервер подключается к туннелю по этому имени.

Сначала скрипт пробует ssh-ключ. Пароль — запасной вариант: он идёт в `sshpass` через переменную окружения, не через аргументы.

> **Сохраните копию папки `secret/`** в надёжном месте (менеджер паролей, зашифрованный архив). Без `tunnel.yaml` туннель не перенастроить, без `clients/` не показать старые конфиги.

## 4. Деплой выходного сервера

```bash
make deploy-exit
```

Ставит модуль AmneziaWG, собирает `awg`/`awg-quick`, кладёт конфиг туннеля, firewall (NAT, запрет частных сетей) и включает `vpn-awg-exit.service`. В конце печатает статус. Если `tunnel.yaml` нет — создаст его.

После этого откройте в облаке UDP-порт туннеля (`port:` из `secret/tunnel.yaml`), лучше только для IP входного сервера.

## 5. Деплой входного сервера

```bash
make deploy
```

Порядок на сервере: тюнинг ядра → AmneziaWG → nft и маршруты → туннель `awg-exit` → `awg0` для клиентов (ключ сервера создаётся только при первой установке) → DNS (unbound) → `vpn-peer` → таймер самопроверки.

В конце печатает состояние четырёх сервисов: `vpn-awg0`, `vpn-awg-exit`, `vpn-routes`, `unbound`. Все должны быть `active`.

`make deploy` остановится, если нет `secret/tunnel.yaml`: иначе входной сервер получил бы ключи, которых не знает выходной.

## 6. Проверка

```bash
./scripts/vpnctl.sh status
```

Должно быть:

```
tunnel: handshake 12s ago
ip rule: ok
table 100: ok
fail-closed route: ok
external IP: 198.51.100.7
ok: traffic leaves from the exit server (198.51.100.7)
```

`external IP` должен совпадать с IP выходного сервера. Если в `exit-access.yaml` указано имя, а не IP, команда покажет WARNING — сравните адреса глазами.

## 7. Клиенты

| Задача | Команда |
| --- | --- |
| Выдать ключ | `./scripts/vpnctl.sh add anna` |
| QR существующего клиента ещё раз (спросит, сохранить ли копию) | `./scripts/vpnctl.sh show anna` |
| Отозвать ключ | `./scripts/vpnctl.sh remove anna` |
| Список (имя, IP, последнее подключение) | `./scripts/vpnctl.sh list` |

Имя: латиница, цифры, `-` и `_`, до 32 символов.

`add` создаёт ключи у вас на компьютере, отправляет на сервер только публичный ключ и PSK, пишет `secret/clients/anna.conf` и печатает QR-код. Клиент ставит **AmneziaVPN** и импортирует файл или сканирует QR.

Добавление и удаление не рвут связь у других клиентов.

## 8. Повторный деплой

`make deploy` и `make deploy-exit` можно запускать сколько угодно раз. Они:

- не меняют ключи (ни туннеля, ни `awg0`);
- не трогают список клиентов;
- не перезапускают `awg0`;
- перезапускают туннель и unbound только если их конфиги изменились.

Если поменялся `tunnel.yaml` — сначала `make deploy-exit`, потом `make deploy`.

## 9. Если что-то не так

| Признак | Что проверить |
| --- | --- |
| `make deploy-exit` падает на ssh | данные в `exit-access.yaml`, ssh-ключ, `sudo` без пароля |
| `status`: `tunnel: DOWN` | открыт ли UDP-порт туннеля на выходном; `make deploy-exit` прошёл; одинаковый `tunnel.yaml` на обоих деплоях |
| `status`: `ip rule: MISSING` | таймер вернёт правило за 15 с; если нет — `systemctl status vpn-routes-check.timer` на входном |
| Клиент подключается, но нет интернета | `status`; у клиента в AmneziaVPN есть handshake; открыт UDP 443 на входном |
| Клиент не подключается | открыт UDP 443; конфиг не обрезан при копировании |

Полезные команды на входном сервере:

```bash
sudo awg show                      # оба интерфейса, handshakes
sudo vpn-peer list                 # клиенты
ip rule show; ip route show table 100
sudo nft list table inet vpn
journalctl -u vpn-routes-check -n 50
```
